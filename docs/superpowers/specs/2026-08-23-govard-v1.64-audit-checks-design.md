# Design: Update skills for Govard v1.64.0 audit checks (profiler + media guard)

**Date:** 2026-08-23
**Status:** Draft for approval

## Context

Govard v1.64.0-beta.2 (PR ddtcorex/govard#168, issue #167) shipped two new audit capabilities:

1. **`profiler` check** — `govard audit run --checks lint,profiler --url <url>` captures a
   Magento stock profiler CSV (MAGE_PROFILER=csvfile) through the project's own web server,
   storing it as a run artifact with SHA-256. Works on nginx, Apache, and hybrid stacks.
   Rerun without `--checks` repeats the latest run's selection.
2. **`lint` media guard** — the lint toolchain now flags PHP files under `pub/media`
   (`M2-LINT-MEDIA`, rule "PHP file in pub/media"). Proven on bebe9: caught 31 GIF89a-polyglot
   webshells.

The maestro-skills catalog still says these don't exist:

- `skills/magento2-linter/SKILL.md:31` — "`lint` is the only audit check Govard implements today;
  any other `--checks` value is rejected"
- `AGENTS.md` lesson — "govard audit implements only the `lint` check"
- `skills/magento2-security-scan/SKILL.md:24` and `skills/magento2-performance-audit/SKILL.md:27`
  — pinned to "As of Govard v1.63.0"; still true for security/performance checks themselves but
  should reference the media guard where relevant
- `skills/govard-magento/SKILL.md` — Code Quality Audit section doesn't mention the profiler check
- No skill documents how to run/interpret the profiler check at all

## Changes (5 files)

1. **`skills/magento2-linter/SKILL.md`**
   - Replace the "only lint" sentence with the v1.64.0 reality: `lint` + `profiler` exist;
     anything else is rejected. Keep the native-gate-is-required policy untouched.
   - In step 2 of the workflow, note `--url` + `profiler` as an optional add-on check and that
     bare rerun inherits the latest run's selection.
   - Add one short subsection (~170–220 words budget) documenting the media guard:
     what M2-LINT-MEDIA findings are, why PHP in pub/media must be treated as an incident
     (webshells), and first-response pointers — not a full IR guide.

2. **`skills/magento2-security-scan/SKILL.md`** — update the version-pinned paragraph: keep
   "no `security` check" claim (still true), add that the lint run now includes the pub/media
   PHP guard, so a lint pass also covers that specific attack surface.

3. **`skills/magento2-performance-audit/SKILL.md`** — same pattern: keep the no-`performance`
   check claim, point to the new Govard-native `profiler` check as the quick machine-captured
   complement to the manual HTML profiler audit (not a replacement — different depth).

4. **`skills/govard-magento/SKILL.md`** — extend the Code Quality Audit section with the
   profiler command example (`--checks lint,profiler --url …`) and one-line description of
   the artifact.

5. **`AGENTS.md`** — rewrite the stale lesson: the boundary to respect is now
   "lint (+ profiler) only; never imply native security/performance gates", keeping the
   original intent (don't overclaim coverage).

## Non-goals

- No new skill files; no changes to forked superpowers content; no manifest/version bumps yet
  (release checklist runs when this work merges).
- No DSH-side changes.
