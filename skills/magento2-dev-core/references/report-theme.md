# Report Theme - Standard HTML Styles

Standard inline CSS for performance audit HTML reports. Every `report.html` generated by `magento2-performance-audit` must use this theme verbatim (inline `<style>`, no external CDN) so all audits share the same visual language: Maestro header lockup, primary accents, Inter stack, cards, badges, KPI grid, checks, tables.

## Structure

Layout rule: every card renders its context note below table markup, never above the data. Rationale: context annotates data the reader has already seen.

```html
<!DOCTYPE html>
<html lang="en">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>{{title}} - {{date}}</title>
<!-- inline <style> above -->
</head>
<body>
<div class="header"><div class="header-inner">{{brand_logo}}<!-- default Maestro lockup, see Brand defaults --><h1>{{title}}</h1><div class="meta">{{meta}}</div></div></div>
<div class="container">
  <div class="kpi">{{kpi}}</div>
  <div class="card"><h2>URLs Audited <span class="badge badge-gray">{{scope}}</span></h2>{{urls}}</div>
  <!-- one .card per Audit Report Template section: Infrastructure, Cache Status, ... Database, Per-Page Query Detail (7 <details>), etc. -->
  <!-- context note below table in each card: context annotates data the reader has already seen -->
  <div class="card" style="border-left:4px solid var(--red)"><h2>Recommendations <span class="badge badge-red">{{count}} actions</span></h2>{{recommendations}}</div>
  <div class="footer">Generated {{date}} from live govard captures on <code>{{host}}</code> (audit <code>{{session}}</code>). <a href="report.md">Markdown</a> · <a href="report.pdf">PDF via Print</a></div>
</div>
</body>
</html>
```

## Usage

- Copy `report-perf.html.template` (with `{{theme_css}}` replaced by `report-theme.css`) and replace `{{title}}`, `{{date}}`, `{{meta}}`, `{{kpi}}`, `{{urls}}`, `{{sections}}`, `{{host}}`, `{{session}}` from the same data that populates `report.md`.
- Render every audited URL as `<td class="url"><code>…</code></td>` (bare `<td>` does not pick up the wrapping rule below); long URLs wrap via `.url,td.url{overflow-wrap:anywhere;word-break:break-all}` instead of overflowing.
- Brand slots `{{brand_logo}}`, `{{brand_colors}}`, `{{brand_font}}` default to the Maestro values below; an overlay replaces all three together, never one alone.
- Header layout: the gradient is full-bleed, but its text lives in `.header-inner`, which uses the same `max-width:1100px` and `24px` side padding as `.container`, so header and card left edges align at every viewport width. Keep both rules in sync if either changes.
- Theme rule: the header is one of the brand-fixed surfaces, set only through the `--header-` tokens, and it stays fixed across light and dark modes; only data tokens follow the mode. Inverting it (a light header in dark mode) reads as a bug, not theming.
- Keep `Per-Page Query Detail` for deep as 7 `<details><summary>home - 363 queries, 42 shapes</summary><table>...</table></details>` blocks (see `report-template.md`); quick may use `Skipped: quick - 3 pages only, Per-Page Detail deferred to deep`.
- PDF via `google-chrome --headless --no-pdf-header-footer --print-to-pdf="report.pdf" "file://$(pwd)/report.html"` - verify with `pdftotext`.

### Brand defaults (Maestro)

The template ships with Maestro defaults in all three slots, so a default render carries the brand: inline SVG lockup, primary accents, Inter with JetBrains Mono for code. Token copies carry the source stamp, which tests pin instead of the values, so drift is detected without duplicating ownership.

`{{brand_logo}}` sits in the header above the title, defaulting to the inline SVG lockup: the Maestro M in white on a blue rounded tile, with the Maestro wordmark in white for the dark header. Default renders keep the SVG, drop the marker line; an overlay fills the marker, drops the default block. Never use an external image reference: single-file HTML stays offline capable with the logo inline.

`{{brand_colors}}` sits on its own line after the `:root` rules and defaults to the Maestro palette already there. An overlay fills it with one `:root` block redefining only tokens from the overlay token map below, header tokens included, which stay fixed in both modes per the theme rule above.

`{{brand_font}}` sits on its own line after the `body` rule and defaults to the Inter stack in `body` plus the JetBrains Mono `code` rule. An overlay replaces it with one `body` rule setting only the family stack, leaving size, line height, and spacing untouched.

### Overlay token map

An overlay rebrands the report by redefining custom properties, never by overriding selectors, so an upstream class rename cannot silently drop its branding. These are the only tokens an overlay may set:

| Token | Role |
|---|---|
| `--bg` | page background |
| `--card` | card background |
| `--border` | card and table lines |
| `--text` | body text |
| `--muted` | secondary text, table headings |
| `--blue` | links and inline accents |
| `--header-bg` | header background, a color or a gradient |
| `--header-text` | header title and meta text |
| `--header-accent` | header bottom border |
| `--header-code-bg` | code chips in the header meta |
| `--link-decoration` | link underline, `none` or `underline` |

Status colors stay stock everywhere.

Each slot takes exactly one construct:

- `{{brand_colors}}` is one `:root{...}` block of tokens from the table above.
- `{{brand_font}}` is one complete `body{font-family:Inter}` rule; put the whole family stack in it.

A bare declaration such as `font-family:Inter;` at the top level of the style block merges into the next selector and drops that rule: the font never applies and links lose their style. Unread properties such as `--brand-primary` change nothing. Keep text tokens at 4.5:1 contrast against their background; a bright accent belongs on `--header-accent`, not on text.

```css
:root{--header-bg:#ffffff;--header-text:#0f172a;--header-accent:#0a84ff;--header-code-bg:#f8fafc;--blue:#2563eb}
body{font-family:Inter,system-ui,sans-serif}
```
